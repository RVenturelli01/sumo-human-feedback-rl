Hybrid Reward Learning

Training one reward/cost model from expert demonstrations and human preferences at the same time, in the SUMO highway driving environment.

1. What the framework does

The HybridAlgorithm learns a single, shared reward model from two heterogeneous feedback sources and then trains a SAC policy on that learned reward. The two sources are:

demonstrations

Expert trajectories drive a Guided Cost Learning / MaxEnt IRL loss that raises the reward on expert behaviour and lowers it on the policy's own sampled behaviour. This is the maxent_2 loss already present in the repo.

preferences

Pairwise preferences over trajectory fragments drive a Bradley–Terry loss (Christiano et al., 2017). Synthetic preferences are generated from the environment's true reward, exactly as in the existing PreferenceAlgorithm.

Both losses back-propagate into the same reward ensemble, so the model is shaped jointly. The goal is to show experimentally that combining demonstrations and preferences beats either source alone.

2. How the two sources are integrated

The reward model is a shared ensemble (make_reward_ensemble) of SumoRewardNet members, one Adam optimizer per member. During each reward-training round, for every member and every gradient step, the demonstration loss and the preference loss are computed on that same member and summed into a single scalar that is back-propagated together (one optimizer.step()). This guarantees both feedback types shape one reward function rather than two disjoint models.

Preference data is collected each iteration by fragmenting the current policy rollout, gathering synthetic preference labels from the true reward, and pushing them into a train/validation PreferenceDataset. The demonstration loss uses the fixed expert-trajectory dataset plus the current rollout as the model/partition sample.

3. Overall loss

total_loss = λdemo · gcl_loss + λpref · preference_loss + regularization
  • gcl_loss — MaxEnt maxent_2 objective: −Eexpert[R] + logsumexp(Rexpert∪model) − log N, the expert+model partition surrogate of Guided Cost Learning.
  • preference_loss — Bradley–Terry cross-entropy: −Σ label · log σ(R̄1 − R̄2) over fragment pairs, where R̄ is the fragment-average reward.
  • regularization — L2 weight decay applied through each member's Adam optimizer (l2_rew). Reward normalization statistics are fit separately and only affect the reward handed to SAC, never the learning objective.

λdemo and λpref are the two hyper-parameters that both weight the sources and select the experimental mode.

4. The three experimental modes

ModeλdemoλprefWhat it uses
pref_only0> 0Preferences only — reduces to the original Christiano-style preference learning on a SAC policy.
demo_only> 00Demonstrations only — reduces to the original DemoAlgorithm MaxEnt IRL.

The mode is derived automatically from the weights and used to name the W&B run/group (sac_hybrid_<mode>) and logged as hybrid/mode_code (0 = pref_only, 1 = demo_only, 2 = hybrid).

5. Running training & evaluation

Launcher (recommended)

MODE=pref_only ./launchers/run_hybrid_SAC.sh
MODE=demo_only ./launchers/run_hybrid_SAC.sh
MODE=hybrid    ./launchers/run_hybrid_SAC.sh

Extra arguments are forwarded as Hydra overrides, e.g. MODE=hybrid ./launchers/run_hybrid_SAC.sh run.seed=1 algo.kwargs.lambda_pref=0.5.

Direct CLI

python scripts/test_hybrid_SAC.py \
    algo.kwargs.lambda_demo=1.0 \
    algo.kwargs.lambda_pref=1.0 \
    run.output_dir=outputs/hybrid

Evaluation

Rich diagnostics are logged every iteration during training (see below). In addition, the script calls algo.evaluate(n_episodes=20) at the end, which runs the deterministic policy on the dedicated evaluation environment and reports mean true return, success rate and expert-action RMSE under the eval_final/ prefix. evaluate() can also be called standalone after loading a checkpoint.

9. Adaptations vs. the original algorithms

  • GCL term is identical to DemoAlgorithm's maxent_2 loss (same _reward_loss).
  • Preference term reproduces PreferenceAlgorithm's Bradley–Terry loss and bootstrap sampling, but the gradient step is shared with the demo term (one combined back-prop per member per step) instead of a separate optimizer loop.
  • Policy optimization reuses the existing SAC + reward-relabel replay buffer path (unchanged) rather than the PPO loop used by the original preference algorithm, so all three modes share one policy-training procedure and one metric set.
  • When λpref=0 the algorithm is exactly the demonstration algorithm; when λdemo=0 it is exactly the preference algorithm. Existing preference/demonstration code is left untouched.

10. Known limitations & future work

  • Preferences are synthetic (generated from the true reward via PreferenceGathererFromReward); no real human labels are used.
  • The demo and preference losses live on different natural scales; the raw λ weights do not normalize for that, so a good hybrid may need tuning of the ratio rather than simply λ = 1. Adaptive/annealed weighting is a natural extension.
  • The MaxEnt partition uses whole-trajectory returns; effective sample size can drop when the reward scale grows (monitored via reward/maxent2_effective_sample_fraction).
  • Synthetic preference labels currently reuse the fast reward; querying preferences from a different criterion (e.g. safety/cost) would let the framework learn a genuine cost model alongside the reward.
  • No offline replay of a fixed preference dataset yet — preferences are collected online from the current rollout each iteration.
