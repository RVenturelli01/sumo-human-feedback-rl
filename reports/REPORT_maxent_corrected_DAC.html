Reward learning da dimostrazioni — MaxEnt IRL + correzione DAC

DemoAlgorithm · loss_type = maxent_corrected · run W&B 7h0zrcbz (demo-sac-debug) · 2026-06-28 · imitazione convergente ≈ 90% arrivi

TL;DR. La pipeline impara un reward dalle dimostrazioni (MaxEnt IRL) e allena un agente SAC su quel reward. Le prime versioni fallivano per due bias opposti (l'agente si suicidava subito, oppure gironzolava senza arrivare). La causa comune è il reward bias dell'absorbing state identificato da Kostrikov et al. 2019 (DAC). Aggiungendo la coda assorbente analitica γ/(1−γ)·r(sa) + giusta regolarizzazione, l'agente converge alla distribuzione di esiti dell'esperto: ~90% arrivi, lunghezza media ~160 (esperto ~164), velocità ~20.

1 · Inquadramento teorico

1.1 — Cosa fa l'algoritmo (IRL, non imitation diretta)

Non è behavioral cloning. È Inverse RL a massima entropia: si assume che l'esperto campioni traiettorie con probabilità proporzionale al reward,

p(τ) = exp(r(τ)) / Z , Z = ∫ exp(r(τ)) dτ (partition function)

La loss è la negative log-likelihood −r(esperto) + log Z: alza il reward sulle traiettorie esperte, lo abbassa su tutte le altre. Tutto il problema è stimare Z. L'agente finale (SAC) ottimizza il reward appreso → recupera la policy a massima entropia consistente con le dimostrazioni, cioè imita la distribuzione di traiettorie dell'esperto, non azione-per-azione.

1.2 — Stima di Z: importance sampling + fusion (GCL)

Le traiettorie non sono campionate uniformemente ma dalla policy dell'agente q. Serve la correzione di importance sampling (Finn et al. 2016, Guided Cost Learning):

log Z ≈ logsumexpi( r(τi)/τ − log q(τi) ) − log N

Rispetto alle varianti storiche (maxent, maxent_2) che omettono −log q (assumendo proposal uniforme → stima distorta), qui è stata implementata la versione consistente di GCL:

  • partizione su demos ∪ rollout accumulati (Alg. 2 di GCL — gli esperti nel denominatore mantengono la loss limitata);
  • fusion distribution q(τ)=(1/K)Σκ qκ(τ) su tutti gli snapshot di policy passati;
  • qdemo degli esperti stimata con una gaussiana per-step sulle azioni.

1.3 — Il bug: survival / loitering bias (absorbing state)

Con return = somma di reward per-step, la scala dipende dalla lunghezza (traiettorie 1–401 step) → la partizione è dominata dalle traiettorie lunghe e l'effective sample size collassa. Peggio: a seconda del segno del reward per-step, l'agente sfrutta lo stato terminale a cui è implicitamente assegnato reward zero:

  • reward per-step negativo → conviene terminare subito (suicidio: off-road allo step 1);
  • reward per-step positivo → conviene non terminare mai (loitering: gira in tondo, timeout).

Sono la stessa malattia, segni opposti. Kostrikov et al. 2019 (DAC) la chiamano reward bias: la gestione implicita (reward 0) dell'absorbing state. La radice teorica è in Ng, Harada & Russell 1999 (solo lo shaping potential-based lascia invariata la policy ottima).

1.4 — La correzione: absorbing-state reward (DAC §4.2)

Si assegna un reward appreso all'absorbing state. Variante analitica usata qui:

RT = Σt γt r(st,at) + [ γT / (1−γ) ] · r(sa)

La coda γ/(1−γ)·r(sa) dà valore al raggiungere il terminale giusto (arrivo) invece di rimandarlo. Applicata solo ai terminali genuini (done AND not timeout: i timeout fanno bootstrap, non sono assorbenti). Lo sconto γ<1 bonus: limita il return → controlla anche ESS/length bias.

Caveat onesto (dal paper stesso): la variante analitica è "much less stable" della self-loop esplicita, perché 1/(1−γ) amplifica un reward appreso. Con γ=0.995 il fattore è ×200 → richiede regolarizzazione robusta (vedi §3).

2.1 — Cuore della loss (return con coda assorbente)

def _traj_return(self, member, traj):
    # return scontato + coda analitica DAC (γ^T/(1-γ)·r(s_a))
    per_step = self._traj_step_rewards(member, traj)          # (T,)
    T = per_step.shape[0]
    if self.gamma < 1.0:
        discounts = self.gamma ** th.arange(T, dtype=th.float32)
        disc_sum  = (discounts * per_step).sum()
        tail = (self.gamma ** T) / (1.0 - self.gamma) * self._absorbing_reward(member, traj)
        return disc_sum + tail
    return per_step.sum()                                     # γ=1: nessuna coda (legacy)

def _absorbing_reward(self, member, traj):
    last = traj[-1]
    # solo terminali genuini: done AND not timeout (i timeout fanno bootstrap)
    status = np.asarray(last.next_status)
    if not last.done or bool(status[self.STATUS_TIMEOUT]):
        return th.zeros((), dtype=th.float32)
    obs    = th.zeros((1, *np.asarray(last.observation).shape), dtype=th.float32)
    act    = th.zeros((1, *np.asarray(last.action).shape),      dtype=th.float32)
    status = th.tensor(status[None], dtype=th.float32)
    return member(obs, act, status, th.ones((1,))).reshape(())

2.2 — Coda nel reward consegnato a SAC (replay buffer, autoritativo)

rewards = self.reward_model.predict(observations, actions, statuses, dones)
if self.gamma < 1.0:
    timeouts = self.timeouts[batch_inds, env_indices]
    true_terminal = dones * (1.0 - timeouts)              # solo absorbing genuini
    if true_terminal.any():
        abs_rew = self.reward_model.predict(np.zeros_like(observations),
                    np.zeros_like(actions), statuses, np.ones_like(dones))
        rewards = rewards + true_terminal * (self.gamma/(1.0-self.gamma)) * abs_rew
